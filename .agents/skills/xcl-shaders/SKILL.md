# Shaders

Pipeline: container (`gpu/xbox.rs`: DXIL `NOBC` → XDAT → XBCH v3 → FSSM) → decode (`gpu/rdna2.rs` plus `rdna2_xbox.rs` console opcodes) → `gpu/recomp` HLSL → `dxc.rs` DXIL. This is the path the runtime uses. `XCL_DIRECT_DXIL` and a compute program whose HLSL exceeds `dxc::UNOPTIMISED_ABOVE` go through `gpu/dxil` instead (`xcl-dxil`).

`rdna2_spec.rs` is generated by `scripts/gen_rdna2.py` from AMD's machine-readable ISA. Console opcodes that gfx10.3 removed (`v_mac_f32`, `v_madmk_f32`, `v_madak_f32`, `v_mad_f32`) stay in `rdna2_xbox.rs` on free opcode numbers. A literal is fetched when any src field is 255, including unused ones (`v_nop ; lit`).

Recompiler model (`gpu/recomp/mod.rs`): scalar branches, structured `if` / loops where possible, skip flags otherwise. Jumps to an outer loop head and jumps into a loop stay in that structured form. SGPRs uniform, VGPRs per lane under EXEC, ballot via `WaveActiveBallot`, cross-lane via `WaveReadLaneAt`. Modes: `Kernel` (tests), `Vertex`, `Pixel`, `Mesh` (CS wave64 plus `mesh_passthrough`), `Geometry` (ES+GS in one CS), compute ABI from the FSSM descriptor. User SGPRs come from `io`. Flat pixel parameter bits stay as the program wrote them.

Flat memory is `ByteAddressBuffer` `mem`. With more than one UMA window every access goes through `xcl_m*` (`emit.rs`): the high bits pick `mem` or `mem1`.., an `xcl_w` outside the windows reads 0 and drops the store, and a 64-bit add or subtract carries across the 4 GiB boundary. `Options::heap_windows` (`XCL_HEAP_WINDOWS=1`, see `xcl-d3d12`) takes window k from `ResourceDescriptorHeap[MEM_HEAP_BASE + xcl_w]` (`MEM_HEAP_BASE` is 4; descriptors 0..4 of that heap are null views). A driver that refuses the heap-window pipeline gets the same shader again in the switch form (`pso::in_switch_form`). A raw window view is at most 4 GiB − 32 bytes.

`s_barrier` in a multi-warp Compute or Mesh program stays safe when a lane has already exited. The split-wave64 exchange defaults to a bounded spin (`docs/wave64-on-wave32.md`, `upper_lanes.rs`). Do not delete the second half to make NVIDIA pass.

`dxc::compile` forces `-O0` above 256 KB of HLSL. DXC 1.8+ is the README recommendation (`XCL_DXC_DIR`). Finished shaders sit in the in-memory `ShaderCache` and in `compile_cached` on disk. The HLSL disk key hashes `TRANSLATOR_SOURCES` in `crates/xcl/build.rs`, which omits `pso.rs` and `gpu/dxil` so those edits do not throw HLSL translations away. Add `pso.rs` to that list, or bump `TRANSLATION_GLUE_REVISION`, only when container parsing, translation options, profiles, or the HLSL after translation changed. Direct and per-lane translations have their own identities (`xcl-dxil`). Hashes fold CRLF to LF. The runtime cache key includes the heap-window bit (`shaders.rs`). `XCL_TRANSLATED_CACHE=0` turns the translated disk cache off. `wait_for_memory` holds a compile when commit is tight, except a compile a title thread is waiting for: those proceed at once, up to six (`WANTED_AT_ONCE`). Workers are every core but one (`XCL_DXC_THREADS`), at normal priority, so a title thread waiting on a pipeline is not stuck behind them.

Tools: `xcl disasm`, `xcl shaders --recomp --example MNEMONIC --compile 64`. `--precompile --used-only` builds only the pipelines an earlier run of the title used. `--export-hlsl` and `--measure-pso` are the HLSL investigation commands. `--direct` is the direct translator (`xcl-dxil`). Dumps of captured shaders only when `XCL_DUMP_SHADERS=1`.

A new mnemonic belongs in `emit.rs` with a GPU test in `gpu/recomp/tests.rs` that encodes via `rdna2::encode` and checks the lane result. Unsupported ops increment the counter and become a comment; do not emit a wrong opcode as if it were done.
